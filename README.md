# GLASS VEIL

Готовые SVG логотипа находятся в `dist/assets/glass-veil-*.svg`.

Небольшой статический хемоинформатический атлас In Silico BBB. Работает без
API, аккаунта, CDN и сборки JavaScript. Белый фон, органическая чёрная тушь,
природные фотографии и прозрачный портретный контур объединяют разделы
атласа-манги. Линии и небольшие цифровые разрывы передают атмосферу
Tokyo Ghoul, Choujin X и Glassy Sky / breakcore без мигания.
Учебные схемы выполнены в Canvas и SVG. Капилляр показан замкнутым объёмным
сосудом с локальным вырезом; четыре уровня приближения сохраняют простую
схематичную рисовку. Декоративный контур обрезан выше одежды и исчезает
у нижнего края карточки.
Сведения об изображениях и шрифтах: [dist/NOTICE.txt](dist/NOTICE.txt).
Подготовка GitHub Pages: [PUBLISHING.md](PUBLISHING.md).

## Запуск

Из папки сайта (`apps/atlas` в основной рабочей копии, корень отдельного репозитория):

```powershell
node serve.mjs
```

Открыть `http://127.0.0.1:4178`. Порт можно изменить через `ATLAS_PORT`.
Сервер доступен только локально. Для хостинга используются только файлы `dist/`.
Команда `npm run build` готовит проверенную копию сайта в `.pages/`.

## Исходники и форматирование

- `dist/index.html` — семантическая разметка глав, карточек и SVG-схемы.
- `dist/styles.css` — базовая вёрстка, элементы управления и адаптивность.
- `dist/atlas.css` — бумага, тушь, оформление панелей и ритмические детали.
- `dist/atmosphere.css` — утверждённое оформление всех разделов и мобильного вида.
- `dist/app.js` — каталог, сравнение, пути переноса и управление движением.
- `dist/microscope.js` — перспективное рисование четырёх уровней ГЭБ.
- `dist/catalog.js` и `dist/structures/` — предрассчитанные данные RDKit.
- `scripts/check-site.mjs` — проверка ресурсов, относительных путей, каталога и синтаксиса.
- `scripts/build-site.mjs` — сборка готового каталога публикации.
- `scripts/export-source.mjs` — экспорт только сайта для отдельного репозитория.

HTML, CSS и JavaScript хранятся в читаемом виде, без минификации. Формат
зафиксирован в `.prettierrc.json`; Prettier нужен только при разработке.
Текст, заголовки, кнопки и подписи схем используют PT Sans (400 и 700),
числа и короткие технические метки — системный Consolas с запасными шрифтами.
Файлы PT Sans поставляются локально в `dist/fonts/`, без запросов к CDN.
Источник: [Google Fonts / ParaType](https://github.com/google/fonts/tree/main/ofl/ptsans);
лицензия SIL OFL 1.1 сохранена рядом с файлами шрифта.
В папке `apps/atlas`:

```powershell
npm ci --ignore-scripts --workspaces=false
npm run format
npm run format:check
npm run check
npm run build
```

Сайт и сервер предпросмотра запускаются без npm-зависимостей.
Инструменты разработки закреплены в `package-lock.json`; пакет сайта изолирован
от основного pnpm workspace. Для optional Python-скриптов используется Ruff
из инструментов разработки основного проекта.

## Что доступно

- 8 структур из реестра проекта; поиск по русскому/английскому названию и SMILES.
- Реальные 2D-структуры и MW, Crippen logP, TPSA, HBD, HBA, кольца и вращаемые связи.
- Пояснения к дескрипторам и ссылки на PubChem.
- Сравнение до трёх молекул на общих шкалах: полосы с числами, интерактивная
  карта logP × TPSA, объяснение разницы и раскрываемая таблица.
  Номера точек связаны со списком названий и значений рядом с картой;
  на телефоне список расположен под графиком. Близкие точки сохраняют
  истинные координаты, их номера разнесены с помощью тонких линий.
- Выбор молекулы и набор для сравнения сохраняются в localStorage браузера.
- Прокрутка приближает объёмную схему: капилляр → эндотелий → липидный
  бислой → структура выбранной молекулы. Размеры уровней условные.
  Раздел движется вместе со страницей, без фиксации полноэкранных сцен.
  Заголовок, рисунок и подпись находятся в отдельных строках своей главы;
  рисунок ограничен собственной областью и не пересекается с обложкой.
  Все уровни — перспективные схемы с плоскими тонами и тонким контуром.
  Приближение зависит от прокрутки и коротко интерполируется к выбранному масштабу;
  после достижения положения перерисовка останавливается. Уровни сменяются мягким
  растворением, капилляр имеет плавный тон и немного изогнутый контур. Кнопки позволяют
  перейти сразу к нужному уровню. При отключении движения позы статичны.
- 6 элементов интерактивной нейроваскулярной схемы и 3 пути: через клетку,
  эффлюкс обратно в кровь, ограничение между клетками. Три частицы повторяют
  выбранный путь; у плотного контакта останавливаются и возвращаются.
  Эритроциты движутся в просвете. Транспортёр и контакт выделяются при выборе
  соответствующего механизма. Вне экрана и в скрытой вкладке движение приостановлено.
- Развёрнутая стенка сосуда с подписями крови и ткани мозга; статичная
  стрелка направления видна и без анимации. Краткая справка о дескрипторах
  встроена в карточку молекулы и раскрывается по запросу.
- Каталог, свойства и схема продолжают композицию атласа: светлые панели
  с тушевыми границами, структура и дескрипторы рядом на широком экране,
  последовательные панели на телефоне. Органический мотив повторяется
  по краям глав, а не в анатомических отношениях.
- Небольшие ритмические штрихи, разрывы линий и растровые детали отсылают
  к glitchcore / breakcore. Они не меняют научные значения и не мерцают.
- Короткое появление структуры (160 мс) и обновление полос (200 мс).
- Общая кнопка паузы, сохранение её состояния, системный reduced motion,
  остановка SVG-анимаций в скрытой вкладке.
- Адаптивная вёрстка и клавиатурная навигация.

Частицы и скорость на схеме иллюстративные. Это не расчёт переноса выбранной
молекулы. Шкалы дескрипторов не являются порогами BBB+ / BBB−.

Набор предрассчитан. Произвольный SMILES, модель BBB+/BBB−, logBB,
клинические рекомендации и серверные расчёты здесь не реализованы.
Расчётные дескрипторы не выдаются за экспериментальные данные или прогноз ГЭБ.

## Происхождение данных

`export_catalog.py` читает SMILES из `bbb/data/substances.py` через AST,
не импортируя приложение. RDKit рассчитывает дескрипторы и рисует структуры.
Для шаро-стержневого вида используются координаты ETKDGv3 с оптимизацией UFF
и ориентацией по главным осям. При неудачном построении используется 2D-схема;
это явно указано в подписи. Конформер не является расчётом переноса через ГЭБ.
Версия RDKit сохраняется в `dist/catalog.js`. Техническая подпись под
карточкой удалена; научные пояснения и ссылки на источники сохранены.
PubChem CID служит ссылкой на вещество; численные дескрипторы не заявлены
как выгрузка значений PubChem. Все данные и изображения поставляются с сайтом.
Проверка официальных источников описана в [SOURCES-AUDIT.md](SOURCES-AUDIT.md).

Для обновления каталога в основном In Silico BBB (нужен RDKit в Python-окружении):

```powershell
.venv/Scripts/python.exe apps/atlas/export_catalog.py
```

Этот Python-скрипт и реестр основного проекта не входят в отдельный репозиторий
сайта. Для его работы достаточно готовых `dist/catalog.js` и `dist/structures/`.

## GitHub Pages

Для публикации только сайта выполните `npm run export:source` и перенесите
содержимое `.source/` в новый репозиторий. Его workflow `.github/workflows/pages.yml`
проверяет сайт и публикует только `.pages/` по адресу
`https://<owner>.github.io/<website-repository>/`.
В Settings → Pages нужно выбрать источник **GitHub Actions**.
Pull request запускает проверки; push в `main` или ручной запуск workflow из `main`
также публикует сайт через официальный `deploy-pages`.
Данные RDKit на CI не пересчитываются.

Основной проект, его история Git и документация не входят в экспорт.
Подробная последовательность: [PUBLISHING.md](PUBLISHING.md).

Эскизы `.qa/`, локальные архивы `design-baselines/` и рабочие материалы `branding/`
исключены из Git. Проверка `npm run check` запрещает неиспользуемые файлы в `dist/`.
Доступ к внешним источникам нужен только при переходе по ссылкам.
